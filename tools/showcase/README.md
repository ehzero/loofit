# 서비스 소개 썸네일 3D 실험실

Expo·React Native 앱과 분리된 TypeScript·Three.js 전용 도구다. 자체
`package.json`과 lockfile을 사용하므로 루트 앱의 의존성 및 모바일 번들에
Three.js와 Vite가 포함되지 않는다.

```bash
npm run showcase:install
npm run showcase
```

브라우저에서 `http://127.0.0.1:4173`을 연다.

## 렌더링 구조

- 출력 아트보드: `3960 × 2868px`
- 패널: `1320 × 2868px` 3장
- 가상 캡처 폭: `4130px` (`1320px` 패널 사이의 `85px` 거터 2개 포함)
- 편집 화면 패널 간격: 약 `85px` (목록 썸네일 폭 대비 약 `6.44%`)
- 단일 `PerspectiveCamera`: 거리 `14000`, CSS 기준 틸트 `50°`, 방위각 `-17.25°`
- 좌표계 변환: CSS의 아래쪽 `+Y`를 Three.js의 위쪽 `+Y`로 바꾸며 X·Z 회전 부호 반전
- 위젯 카드: 둥근 사각형 `Shape`을 `ExtrudeGeometry`로 돌출하고 앞면·옆면 접합부에 1.25 단위의 미세한 2단 베벨을 적용한 메시
- 잠금화면 위젯: 원형 다음 운동·최근 7일과 직사각형 다음 운동·루틴 진행을 별도 Mesh로 배치
- 휴대폰: `GLTFLoader`로 iPhone 17 Pro Max Silver 모델을 불러와 실제 프레임·버튼·카메라 메시 사용
- 앞면 UI: 투명 배경의 4배 해상도 `CanvasTexture`를 메시 앞면 material group에 직접 매핑
- 재질: 위젯 앞면은 조명에 흔들리지 않는 `MeshBasicMaterial`, 옆면은 무광 `MeshStandardMaterial`을 사용하고 텍스처는 UI 내용만 알파 합성
- 접지감: `DirectionalLight` shadow map과 투명 `ShadowMaterial` catcher
- HTML: 실험 도구 모음, WebGL canvas, 분리된 편집 패널과 패널 가이드만 유지

별도 UI `PlaneGeometry`를 두지 않으므로 라운딩과 두께가 바뀌어도 앞면이
몸체에서 분리되지 않는다. 위젯 텍스처에는 배경색이나 가상 광택을 그리지 않고,
옆면 메시만 조명을 받아 두께와 그림자를 만들고 앞면 UI는 원래 색상과 선명도를 유지한다. `config.ts`가 장면 크기·카메라·카드 배치의 원천이고, `fixtures.ts`가 캡처용
고정 데이터를 제공한다. `three/textures.ts`는 위젯과 휴대폰 앞면을 그리며,
`three/scene.ts`는 모든 메시를 하나의 공통 장면에 배치한다.

카드 배치는 `SHOWCASE_GAP`의 40 단위 간격을 아이폰과 위젯 사이,
위젯과 위젯 사이에 공통 적용한다. Small·Square·Medium 크기를 상·하·좌·우
4방향 링에 교차 배치하고, 좌우 열과 상하 행은 아이폰 가장자리를 향해 맞춘다.
각 위젯은 아이폰 또는 인접 위젯과 정확히 40 간격으로 연결된다. 아이폰 좌우의
3개 위젯 열은 위젯 사이에 40 간격을 두고 열의 시작·끝을 아이폰 프레임과 맞춰,
열 전체 높이가 아이폰 높이와 동일한 650이 되도록 한다.
잠금화면 원형 위젯은 상단 행 바깥쪽, 직사각형 위젯은 하단 행 바깥쪽에 두어
홈 화면 위젯과 형태를 구분하면서 동일한 40 간격을 유지한다.
첫 번째와 마지막 1320px 장의 상단에는 서비스 소개 문구를 HTML 오버레이로
배치한다. 문구는 Three.js 텍스처나 Mesh에 포함하지 않으며 테마·액센트 CSS
변수를 따라가고 촬영 모드에서도 캔버스와 함께 표시된다.
`App Store 미리보기`는 WebGL 캔버스에 독립 렌더링된 1320×2868 세 장을 CSS
아이폰 프레임 안의 App Store 화면에 복사한다. `제품 페이지` 모드는 실제 제품
페이지처럼 가로 스크롤과 스냅이 가능한 스크린샷 캐러셀을 제공하고, `앱 목록`
모드는 검색 결과의 앱 정보 아래에 첫 세 장을 한 줄로 모두 표시한다. 첫 장과
마지막 장의 HTML 문구는 두 모드 모두 축소된 DOM 오버레이로 다시 합성한다.
WebGL 캔버스 자체는 연속된 3960px 화면을 단순 삼등분하지 않는다. Three.js
`PerspectiveCamera.setViewOffset`으로 `0`, `1405`, `2810`에서 각각 1320px를
렌더링하고, 두 패널 사이의 가상 85px 구간은 생략한다. 따라서 출력은 여전히
3960×2868이지만 App Store 카드 사이의 물리적 간격 뒤로 같은 물체가 바로
이어지는 파노라마식 연결은 발생하지 않는다.
도구 모음의 `이미지 자름`을 끄면 가상 거터 없이 3960px 연속 카메라로
돌아가며 편집 화면도 다시 하나의 아트보드로 합쳐진다. 자름을 켜면 편집
화면에서 세 패널을 약 85px씩 띄워 App Store 목록의 카드 간격 비율을 함께
확인한다. 이 값은 430pt 목록 화면에서 좌우 4.8% 여백과 8pt 간격을 제외한
스크린샷 한 장의 표시 폭을 계산한 뒤, 같은 비율을 1320px 패널에 적용한 값이다.
가상 생략 구간과 편집 화면의 표시 간격은 같은 `85px` 값을 공유하므로 캐러셀
간격보다 더 많은 장면이 경계에서 사라지지 않는다.
촬영 모드에서는 표시용 간격을 제거하고 3960×2868 출력만 보여 준다.

Apple은 [App Store 검색 안내](https://developer.apple.com/app-store/search/)에서
방향과 플랫폼에 따라 최대 3장의 스크린샷이 검색 결과에 표시된다고 설명하지만,
카드 사이 간격의 정확한 수치는 공개하지 않는다. `8pt`는 현재 iPhone 목록 UI의
비율을 기준으로 한 미리보기용 추정값이며 OS 버전과 기기에 따라 달라질 수 있다.

휴대폰 모델의 `17ProMax_Screen` 재질은 로드 후 루핏 홈 화면
`CanvasTexture`로 교체한다. 화면은 mipmap과 조명·깊이 합성을 우회해 원본 UI
색상과 해상도를 유지한다. 다이내믹 아일랜드의 검은 캡슐은 화면 텍스처에 직접
그려 조명과 무관하게 유지한다. 화면을 모델의 전면 렌즈 Mesh보다 늦게 렌더링하고
캡슐에 소량의 오버스캔을 두어 렌즈와 주변 형상이 검은 영역 밖으로 노출되지 않는다.
모델의 원래 Y축 크기를 쇼케이스 휴대폰 높이에 맞춰
균일 양수 스케일과 Y축 180도 회전으로 화면이 공통 카메라를 향하도록 배치한다.
전체 모델의 카메라 돌출부가 아니라 넓은 뒷판과 같은 평면에 놓인 Apple 로고
메시를 접지 기준으로 사용해 본체 뒷판을 바닥 `z=0`에 맞춘다. 후면 카메라·렌즈
전용 메시는 로드 시 숨기고 본체 메시와 합쳐진 돌출 정점은 뒷판 평면까지
투영해, 원본 모델 파일을 수정하지 않고 평평한 전면 목업으로 사용한다.
프레임은 `config.ts`의 `PHONE_MODEL.frameColors`·`metalness`·`roughness`로
지정하며 라이트 테마는 실버, 다크 테마는 딥 블루를 사용한다. 중립
`RoomEnvironment` 반사를 적용해 금속 재질이 검게 죽지 않도록 한다.

도구 모음의 `3D 조절` 패널에서 메시 두께·모서리 라운딩·바닥 Z 위치,
카메라 틸트·방위각·원근 거리·장면 줌과 화면 기준 그림자 방향·벌어짐·부드러움,
조명 세기를 실시간으로 변경할 수 있다. 원근 거리는 투영 왜곡 강도를 바꾸고,
`0.60×~1.60×` 장면 줌은 같은 원근감에서 전체 Mesh를 확대·축소한다.
그림자 방향은 `0°` 오른쪽, `90°` 아래,
`180°` 왼쪽, `270°` 위로 고정하고 카메라와 바닥 회전을 월드 광원 방향으로
역산한다. `그림자 벌어짐`은 광원의 투사 기울기를 바꿔 그림자가 방향축을 따라
떨어지는 비율을 조절하고, 바닥 높이 Z는 실제 이격 거리에 함께 영향을 준다.
메시의 기본 Z는 `0`이므로 바닥에 놓이며, `기본값` 버튼은
`DEFAULT_VIEW_CONTROLS`로 모든 값을 되돌린다. 위젯 두께와 라운딩은 절차적으로
생성한 위젯에만 적용한다. 가져온 휴대폰 모델은 원본 비율과 두께를 유지하며
공통 바닥 Z 위치만 따른다.

## 모바일 앱과의 격리

- 루트 `package.json`에는 Three.js·Vite 의존성을 추가하지 않는다.
- Expo 앱 코드에서 `tools/showcase`를 import하지 않는다.
- `.easignore`에서 `/tools/showcase/`를 제외해 EAS 모바일 빌드 컨텍스트에도 업로드하지 않는다.
- 실험실 빌드 결과인 `tools/showcase/dist`와 전용 `node_modules`는 Git에서 제외된다.
