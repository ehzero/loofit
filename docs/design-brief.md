# 핏로그 앱 디자인 브리프

이 문서는 핏로그의 앱 및 위젯 디자인을 맡는 디자이너가 제품 맥락, 핵심 개념, 주요 화면, 상태, 플로우, 산출물을 이해하기 위한 문서다.

## 1. 서비스 개요

핏로그는 운동을 자세히 기록하는 앱이 아니라, **내 운동 루틴을 기억하고 다음 운동을 알려주는 가벼운 운동 기록 앱**이다.

사용자는 세트 수, 중량, 반복 횟수, 운동 종목을 기록하지 않는다. 대신 “운동 시작”과 “운동 종료”만 누르면 운동 시간과 운동 부위가 기록된다.

핵심 문장은 다음과 같다.

> 내 루틴대로, 운동을 가볍게 기록하세요.

핏로그는 “운동을 자세히 분석하는 앱”이 아니라, **내 운동 루틴을 가볍게 기록하고 이어가게 해주는 앱**이다.

## 2. 왜 필요한가

헬스를 꾸준히 하는 사람 중에는 매번 세트, 중량, 반복 횟수를 기록하는 것을 귀찮아하는 사람이 많다. 하지만 그렇다고 아무 기록도 남기지 않으면 내가 언제 어떤 부위를 운동했는지, 루틴을 얼마나 꾸준히 이어가고 있는지 흐려진다.

핏로그는 이런 사용자를 위한 앱이다.

- 오늘 어떤 루틴을 해야 하는지 헷갈리고 싶지 않다.
- 자세한 운동 기록은 부담스럽다.
- 그래도 운동 여부와 운동 시간은 남기고 싶다.
- 내 루틴이 끊기지 않고 이어지고 있는지 보고 싶다.
- 기록이 쌓이는 것을 보며 동기부여를 얻고 싶다.

즉, 핏로그는 “운동 분석 앱”이라기보다 **내 운동 루틴을 가볍게 기록하고 이어가게 해주는 도구**에 가깝다.

## 3. 타깃 사용자

주요 사용자는 헬스를 어느 정도 꾸준히 하는 사람이다. 운동 자체를 처음 시작하는 초보자보다는, 이미 “가슴/등/하체”, “PPL”, “상하체” 같은 분할 루틴 개념을 알고 있는 사람에 가깝다.

이 사용자는 다음과 같은 특징을 가진다.

- 헬스장에 가는 습관은 어느 정도 있다.
- 매번 어떤 운동을 해야 할지 헷갈릴 때가 있다.
- 세트/중량 기록 앱을 써봤지만 귀찮아서 포기한 경험이 있다.
- 운동을 했는지, 얼마나 했는지만 기록해도 충분하다고 느낀다.
- 캘린더나 히트맵처럼 누적되는 기록을 보는 데 동기부여를 느낀다.

## 4. 핵심 개념

핏로그에는 세 가지 핵심 개념이 있다.

### 4.1 운동 부위

운동 부위는 기록의 가장 작은 운동 대상 단위다.

예:

- 가슴
- 등
- 하체
- 어깨
- 팔
- 유산소
- 코어
- 기타

사용자는 자신의 운동 부위를 직접 추가하거나 관리할 수 있다.

### 4.2 루틴

루틴은 사용자가 반복해서 수행하는 운동 흐름이다. 하나의 루틴 안에는 어떤 분할 방식으로 운동할지, 각 분할에 어떤 부위를 묶을지 같은 세부 구성이 들어간다.

예를 들어 PPL 루틴은 다음처럼 구성된다.

- Push: 가슴 + 어깨 + 삼두
- Pull: 등 + 이두
- Legs: 하체

3분할 루틴은 다음처럼 구성될 수 있다.

- 가슴 + 삼두
- 등 + 이두
- 하체 + 어깨

### 4.3 다음 운동

다음 운동은 사용자가 설정한 루틴 순서에 따라 다음에 수행해야 할 운동일을 의미한다. AI가 추천하는 방식이 아니라, 사용자가 정한 루틴 순서를 그대로 따라가는 방식이다.

예를 들어 PPL 루틴에서 마지막으로 Push를 완료했다면, 앱은 다음 운동으로 Pull을 안내한다. Pull을 완료하면 다음 운동은 Legs가 되고, Legs를 완료하면 다시 Push로 돌아간다.

## 5. 루틴 진행 방식

루틴은 날짜 기준으로 자동 이동하지 않는다. 핏로그에서 다음 운동으로 넘어가는 기준은 **완료된 운동 세션**이다.

예를 들어 오늘 Push를 완료하면 다음 운동은 Pull이 된다. 하루에 운동을 두 번 해서 Push와 Pull을 모두 완료하면, 루틴은 두 칸 넘어가 다음 운동은 Legs가 된다.

중요한 정책은 다음과 같다.

- 완료된 루틴 운동만 다음 운동 계산에 반영된다.
- 앱이 알려준 다음 운동과 다른 루틴을 선택해 완료해도, 실제 완료한 루틴 기준으로 다음 순서가 정해진다.
- 루틴 밖 자유 운동은 기록만 남고 다음 운동 계산에는 반영되지 않는다.
- 취소한 운동은 기록에는 남지만 다음 운동 계산에는 반영되지 않는다.
- 운동 기록을 나중에 수정하거나 삭제해도 다음 운동은 자동으로 재계산하지 않는다.
- 다음 운동이 어긋났다고 느끼면 사용자가 루틴 설정에서 직접 시작점을 바꾼다.
- 루틴의 구성과 순서는 사용자가 직접 바꾸기 전까지 자동으로 바뀌지 않는다.

## 6. 운동 세션

운동 세션은 사용자가 운동을 시작하는 순간 생성된다.

운동 중에는 다음 정보가 중요하다.

- 현재 운동 부위
- 시작 시간
- 경과 시간
- 종료 액션
- 취소 액션
- 운동 변경 액션

운동을 종료하면 다음 정보가 기록된다.

- 시작 시간
- 종료 시간
- 총 운동 시간
- 운동 부위 스냅샷
- 연결된 루틴
- 상태: 완료 또는 취소
- 메모, 선택 사항

운동 부위 스냅샷을 저장하는 이유는, 나중에 루틴이나 운동 부위 이름이 바뀌더라도 과거 기록은 당시 기준으로 보여주기 위해서다.

## 7. 앱에서 가능한 일

앱은 위젯보다 더 세밀한 조작을 담당한다.

앱에서 가능한 주요 동작은 다음과 같다.

- 다음 운동 시작
- 다른 루틴 선택 후 시작
- 루틴 밖 자유 운동 시작
- 운동 종료
- 운동 취소
- 운동 중 운동 대상 변경
- 루틴 설정
- 운동 부위 추가 및 관리
- 다음 운동 시작점 선택
- 운동 기록 확인
- 운동 기록 수정
- 운동 기록 삭제
- 히트맵 확인
- 대시보드 확인

## 8. 홈 화면의 역할

핏로그의 홈 화면은 앱의 중심 화면이다.

운동 중이 아닐 때 홈 화면은 다음 운동을 시작하기 위한 화면이다. 사용자는 홈 화면에서 다음 운동을 확인하고, 바로 운동을 시작할 수 있다. 필요하다면 다음 운동이 아닌 다른 루틴을 선택하거나, 루틴 밖 자유 운동을 시작할 수도 있다.

운동 중일 때는 홈 화면 자체가 운동 중 화면 역할을 한다. 별도의 운동 중 화면으로 이동하지 않아도, 홈 화면에서 현재 운동 상태를 바로 볼 수 있다.

운동 중 홈 화면에서는 다음 정보를 보여준다.

- 운동 중 상태
- 현재 운동 부위
- 시작 시간
- 경과 시간
- 운동 종료
- 운동 취소
- 운동 변경

즉, 사용자는 앱을 열었을 때 항상 홈 화면에서 현재 해야 할 일을 바로 알 수 있다.

- 운동 전이면 다음 운동을 시작한다.
- 운동 중이면 현재 운동을 확인하고 종료한다.
- 운동 후에는 오늘의 기록과 누적 기록을 확인한다.

## 9. 위젯에서 가능한 일

핏로그에는 두 가지 위젯이 있다.

### 9.1 운동 시작/종료 위젯

이 위젯은 앱을 열지 않고 운동을 시작하거나 종료하기 위한 위젯이다.

상태는 세 가지다.

운동 전:

- 다음 운동
- 포함된 운동 부위
- 운동 시작 액션

운동 중:

- 운동 중 상태
- 현재 운동 부위
- 경과 시간
- 운동 종료 액션

운동 후:

- 오늘 운동 완료 상태
- 완료한 운동
- 운동 시간

운동을 종료한 뒤에는 당일 자정까지 완료 상태를 보여준다. 다음 날이 되면 다시 운동 전 상태로 돌아간다.

위젯에서는 복잡한 조작을 하지 않는다. 다른 루틴 선택, 자유 운동 선택, 루틴 수정, 기록 수정은 앱 안에서만 한다.

### 9.2 히트맵 캘린더 위젯

이 위젯은 운동 기록을 빠르게 확인하기 위한 위젯이다.

디자이너는 다음을 설계해야 한다.

- 7일 히트맵
- 30일 히트맵
- 운동 시간 강도 단계
- 운동한 날과 안 한 날의 차이
- 작은 위젯과 중간/큰 위젯의 정보 밀도 차이

핵심 질문:

> 사용자가 홈 화면에서 최근 운동 흐름을 빠르게 확인할 수 있는가?

## 10. 히트맵

히트맵은 운동 여부와 운동 시간을 날짜별로 보여준다.

기준은 단순히 그날의 총 운동 시간이다.

- 운동 안 함
- 30분 미만
- 30분 이상 60분 미만
- 60분 이상 90분 미만
- 90분 이상

하루에 여러 번 운동하면 해당 날짜의 운동 시간이 합산된다. 취소한 운동은 히트맵과 운동 시간 통계에는 포함하지 않는다.

## 11. 디자이너 작업 범위

디자이너는 핏로그의 MVP 경험을 기준으로, 앱과 위젯의 핵심 사용 흐름을 설계한다.

핏로그는 기능이 많은 앱이 아니라, 사용자가 운동 전후에 아주 짧게 사용하는 앱이다. 따라서 디자인의 목표는 많은 정보를 보여주는 것이 아니라, 사용자가 현재 상태에서 해야 할 일을 즉시 이해하게 만드는 것이다.

디자이너가 설계해야 하는 것은 크게 세 가지다.

1. 앱 화면
2. 위젯
3. 핵심 상태와 사용 흐름

## 12. 앱 화면 디자인 범위

### 12.1 홈 화면

홈 화면은 핏로그의 중심 화면이다. 운동 전, 운동 중, 운동 후 상태를 모두 처리해야 한다.

디자이너는 홈 화면을 다음 세 가지 상태로 나누어 설계해야 한다.

#### 운동 전 상태

사용자가 아직 운동을 시작하지 않은 상태다.

이 상태에서 홈 화면은 다음을 보여줘야 한다.

- 다음 운동
- 해당 루틴에 포함된 운동 부위
- 운동 시작 액션
- 다른 루틴 선택
- 루틴 밖 자유 운동 선택
- 최근 히트맵
- 이번 주 운동 횟수
- 총 운동 시간
- 최근 기록

핵심 질문:

> 사용자가 앱을 열자마자 “오늘은 무엇을 하면 되는지” 알 수 있는가?

#### 운동 중 상태

사용자가 운동을 시작한 뒤 아직 종료하지 않은 상태다. 이 상태에서는 홈 화면 자체가 운동 중 화면 역할을 한다.

이 상태에서 홈 화면은 다음을 보여줘야 한다.

- 운동 중 상태
- 현재 운동 부위
- 시작 시간
- 경과 시간
- 운동 종료 액션
- 운동 취소 액션
- 운동 변경 액션
- 필요하다면 최근 기록 또는 히트맵은 낮은 우선순위로 배치

핵심 질문:

> 사용자가 운동 중 앱을 열었을 때, 바로 경과 시간을 보고 종료할 수 있는가?

#### 운동 후 상태

오늘 운동을 완료했거나 취소한 상태다.

이 상태에서 홈 화면은 다음을 보여줘야 한다.

- 오늘 완료한 운동
- 운동 시간
- 다음 운동
- 최근 히트맵
- 이번 주 운동 횟수
- 총 운동 시간
- 최근 기록

핵심 질문:

> 사용자가 운동이 기록되었다는 확신을 얻을 수 있는가?

### 12.2 루틴 설정 화면

루틴 설정 화면은 사용자가 자신의 운동 루틴을 구성하는 화면이다.

디자이너는 다음 개념이 자연스럽게 이해되도록 설계해야 한다.

- 운동 부위
- 루틴
- 분할
- 각 분할에 포함된 부위
- 다음 운동 시작점

루틴 설정 화면에서 사용자는 다음을 할 수 있어야 한다.

- 기본 템플릿으로 루틴 만들기
- 운동 부위 추가
- 운동 부위 보관 또는 삭제
- 루틴 안에 분할 추가
- 분할 이름 수정
- 분할에 포함된 운동 부위 수정
- 분할 순서 변경
- 분할 삭제
- 다음 운동 시작점 선택

핵심 질문:

> 사용자가 “내 루틴이 어떤 순서로 돌아가는지” 이해하고 수정할 수 있는가?

### 12.3 기록 목록 화면

기록 목록 화면은 과거 운동 기록을 확인하는 화면이다.

디자이너는 다음 상태를 고려해야 한다.

- 완료된 운동
- 취소된 운동
- 진행 중인 운동
- 기록이 없는 상태

기록 목록에서는 다음 정보가 보여야 한다.

- 운동 날짜
- 운동 부위
- 상태
- 운동 시간
- 루틴 운동인지 자유 운동인지 구분

핵심 질문:

> 사용자가 최근 운동 기록을 빠르게 훑어볼 수 있는가?

### 12.4 기록 상세 화면

기록 상세 화면은 기록을 수정하거나 삭제하는 화면이다.

디자이너는 다음을 설계해야 한다.

- 운동 상태 수정
  - 완료
  - 취소
  - 진행 중
- 시작 시간 수정
- 종료 시간 수정
- 운동 대상 수정
  - 루틴 운동
  - 자유 운동
- 메모 수정
- 기록 삭제

주의할 점:

기록 상세 화면은 개발자용 입력 화면처럼 보이면 안 된다. 예를 들어 ISO 날짜 문자열을 그대로 입력하게 하는 방식은 사용자가 이해하기 어렵다.

핵심 질문:

> 사용자가 실수로 잘못 저장된 운동 기록을 쉽게 고칠 수 있는가?

### 12.5 대시보드 화면

대시보드 화면은 누적 운동 기록을 확인하는 화면이다.

디자이너는 다음 정보를 설계해야 한다.

- 최근 7일 히트맵
- 최근 30일 히트맵
- 이번 주 운동 횟수
- 총 운동 시간
- 부위별 운동 시간
- 최근 운동 기록 요약

핵심 질문:

> 사용자가 자신의 운동 패턴을 한눈에 이해할 수 있는가?

### 12.6 설정 화면

설정 화면은 MVP에서는 보조적인 화면이다.

디자이너는 다음 정도만 고려하면 된다.

- 앱 기본 정보
- 로컬 데이터 초기화
- 추후 확장될 설정 항목이 들어갈 수 있는 구조

핵심 질문:

> MVP에서 필요한 최소 설정만 제공하면서도 어색하지 않은가?

## 13. 핵심 플로우 디자인

디자이너는 개별 화면뿐 아니라, 사용자가 실제로 겪는 흐름을 함께 설계해야 한다.

### 13.1 첫 사용 흐름

사용자가 앱을 처음 열었을 때의 흐름이다.

필요한 흐름:

1. 루틴이 없음을 인지
2. 기본 템플릿 선택 또는 직접 루틴 생성
3. 다음 운동 확인
4. 첫 운동 시작

핵심 질문:

> 사용자가 첫 운동 기록까지 막히지 않고 도달하는가?

### 13.2 운동 시작 흐름

운동을 시작하는 흐름이다.

필요한 흐름:

1. 홈에서 다음 운동 확인
2. 운동 시작
3. 홈이 운동 중 상태로 전환
4. 경과 시간 확인

다른 선택지도 고려해야 한다.

- 다음 운동이 아닌 다른 루틴 시작
- 루틴 밖 자유 운동 시작

핵심 질문:

> 운동 시작까지 걸리는 시간이 충분히 짧은가?

### 13.3 운동 종료 흐름

운동을 끝내는 흐름이다.

필요한 흐름:

1. 홈 또는 위젯에서 운동 중 상태 확인
2. 운동 종료
3. 완료 상태 확인
4. 기록과 히트맵 반영 확인

핵심 질문:

> 사용자가 운동이 정상적으로 기록되었다고 확신할 수 있는가?

### 13.4 운동 취소 흐름

운동을 잘못 시작했거나 실제로 운동하지 않은 경우의 흐름이다.

필요한 흐름:

1. 운동 중 상태에서 취소 선택
2. 취소 기록으로 남음
3. 루틴은 진행되지 않음
4. 기록 상세에서 수정 또는 삭제 가능

핵심 질문:

> 실수로 시작한 운동을 부담 없이 처리할 수 있는가?

### 13.5 루틴 수정 흐름

사용자가 루틴을 변경하는 흐름이다.

필요한 흐름:

1. 현재 루틴 확인
2. 분할 추가/수정/삭제/정렬
3. 운동 부위 수정
4. 다음 운동 시작점 선택
5. 홈에서 다음 운동 반영 확인

핵심 질문:

> 사용자가 루틴을 바꾼 뒤 다음 운동이 무엇인지 명확히 알 수 있는가?

### 13.6 기록 수정/삭제 흐름

사용자가 과거 기록을 수정하는 흐름이다.

필요한 흐름:

1. 기록 목록에서 기록 선택
2. 기록 상세 확인
3. 시간, 상태, 운동 대상, 메모 수정
4. 저장
5. 기록 삭제 가능

주의할 점:

기록을 수정하거나 삭제해도 다음 운동은 자동으로 재계산되지 않는다. 이 정책이 사용자에게 혼란을 주지 않도록 화면에서 맥락이 필요할 수 있다.

핵심 질문:

> 사용자가 기록은 고칠 수 있지만, 다음 운동은 별도 설정에서 조정해야 한다는 점을 이해할 수 있는가?

## 14. 최종 산출물

디자이너는 최소한 다음 산출물을 만든다.

### 14.1 앱 화면

- 홈 화면
  - 운동 전 상태
  - 운동 중 상태
  - 운동 후 상태
- 루틴 설정 화면
- 기록 목록 화면
- 기록 상세 화면
- 대시보드 화면
- 설정 화면

### 14.2 위젯

- 운동 시작/종료 위젯
  - 운동 전 상태
  - 운동 중 상태
  - 운동 후 상태
- 히트맵 캘린더 위젯
  - 7일 타입
  - 30일 타입

### 14.3 주요 상태

- 루틴이 없는 상태
- 운동 기록이 없는 상태
- 운동 중 상태
- 운동 완료 상태
- 운동 취소 상태
- 루틴 수정 후 다음 운동 시작점 선택 상태

### 14.4 주요 플로우

- 첫 루틴 생성
- 운동 시작
- 운동 종료
- 운동 취소
- 다른 루틴 선택 후 운동 시작
- 자유 운동 시작
- 루틴 수정
- 기록 수정
- 기록 삭제

### 14.5 컴포넌트 또는 패턴

핏로그는 반복되는 정보 구조가 많기 때문에, 다음 패턴을 정의하면 좋다.

- 루틴 카드 또는 루틴 row
- 운동 기록 row
- 운동 부위 chip
- 상태 badge
- 운동 시작 CTA
- 운동 종료 CTA
- 히트맵 셀

- 빈 상태
- 삭제/취소 확인 패턴

## 15. MVP에서 다루지 않는 것

핏로그 MVP는 의도적으로 많은 기능을 제외한다.

MVP에서 제외되는 것은 다음과 같다.

- 세트 기록
- 중량 기록
- 반복 횟수 기록
- 운동 종목 데이터베이스
- AI 코칭
- 식단 기록
- 체중 기록
- 커뮤니티
- 친구 공유
- 클라우드 동기화
- 구독 결제
- 1년 히트맵
- 운동 일시정지
- 운동 중 여러 구간 분리 기록

## 16. 요약

디자이너는 단순히 “예쁜 화면”을 만드는 것이 아니라 다음을 설계해야 한다.

> 사용자가 지금 운동 전인지, 운동 중인지, 운동 후인지 즉시 이해하고, 그 상태에서 해야 할 일을 바로 수행할 수 있는 앱과 위젯 경험.
