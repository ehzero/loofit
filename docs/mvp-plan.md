# 핏로그 MVP 기획서

작성일: 2026-07-09  
상태: MVP 검토본

## 1. 제품 정의

핏로그는 운동을 자세히 기록하는 앱이 아니라, **내 운동 루틴을 기억하고 다음 운동을 알려주는 가벼운 운동 기록 앱**이다.

사용자는 세트 수, 중량, 반복 횟수, 운동 종목을 기록하지 않는다. 대신 “운동 시작”과 “운동 종료”만 누르면 운동 시간과 운동 부위가 기록된다.

핏로그는 “운동을 자세히 분석하는 앱”이 아니라, **내 운동 루틴을 가볍게 기록하고 이어가게 해주는 앱**이다.

## 2. 제품 한 줄 문구

내 루틴대로, 운동을 가볍게 기록하세요.

## 3. 핵심 가치

- 오늘 어떤 운동을 해야 하는지 헷갈리지 않는다.
- 운동 시작과 종료가 빠르다.
- 내 운동 기록을 한눈에 확인한다.
- 루틴이 끊기지 않고 이어지는지 확인할 수 있다.

## 4. 타깃 사용자

- 헬스는 꾸준히 하지만 자세한 기록은 귀찮은 사람
- 세트, 중량 기록 앱을 쓰다 포기한 사람
- 분할 루틴대로 운동하지만 매번 기록하기 귀찮은 사람
- 운동 여부와 운동 시간을 가볍게 남기고 싶은 사람
- 캘린더나 히트맵처럼 누적되는 기록에서 동기부여를 얻는 사람

## 5. 핵심 개념

### 5.1 운동 부위

운동 부위는 기록의 가장 작은 운동 대상 단위다.

기본 제공 부위:

- 가슴
- 등
- 하체
- 어깨
- 팔
- 삼두
- 이두
- 유산소
- 상체
- 푸시
- 풀
- 코어
- 기타

기본 부위는 초기값일 뿐이며, 사용자는 자신의 운동 부위를 직접 추가하거나 관리할 수 있다.

### 5.2 루틴

루틴은 사용자가 반복해서 수행하는 운동 흐름이다.

하나의 루틴 안에는 어떤 분할 방식으로 운동할지, 각 분할에 어떤 부위를 묶을지 같은 세부 구성이 들어간다.

예를 들어 PPL 루틴은 다음처럼 구성된다.

- Push: 가슴 + 어깨 + 삼두
- Pull: 등 + 이두
- Legs: 하체

3분할 루틴은 다음처럼 구성될 수 있다.

- 가슴 + 삼두
- 등 + 이두
- 하체 + 어깨

### 5.3 다음 운동

다음 운동은 사용자가 설정한 루틴 순서에 따라 다음에 수행해야 할 운동을 의미한다. AI가 추천하는 방식이 아니라, 사용자가 정한 루틴 순서를 그대로 따라가는 방식이다.

예를 들어 PPL 루틴에서 마지막으로 Push를 완료했다면, 앱은 다음 운동으로 Pull을 안내한다. Pull을 완료하면 다음 운동은 Legs가 되고, Legs를 완료하면 다시 Push로 돌아간다.

## 6. 제품 원칙

- 다음 운동은 AI가 아니라 사용자가 설정한 루틴 순서 기반으로 정해진다.
- MVP에서는 세트, 중량, 반복 횟수, 운동 종목 DB를 다루지 않는다.
- 운동 기록의 최소 단위는 “운동 부위 + 시작 시간 + 종료 시간”이다.
- 사용자가 다음 운동을 그대로 시작할 수 있어야 한다.
- 사용자가 다음 운동 대신 루틴 안의 다른 분할을 선택할 수 있어야 한다.
- 루틴 밖 자유 운동은 기록할 수 있지만 루틴 진행에는 반영하지 않는다.
- 기록은 로컬 우선 구조로 저장한다.
- 위젯과 Live Activity는 운동 중 상태 확인과 빠른 시작/종료에 집중한다.
- 홈 화면은 운동 전, 운동 중, 운동 후 상태를 모두 처리하는 앱의 중심 화면이다.

## 7. 루틴 진행 방식

루틴은 날짜 기준으로 자동 이동하지 않는다. 핏로그에서 다음 운동으로 넘어가는 기준은 **완료된 운동 세션**이다.

중요한 정책은 다음과 같다.

- 완료된 루틴 운동만 다음 운동 계산에 반영된다.
- 앱이 알려준 다음 운동과 다른 분할을 선택해 완료해도, 실제 완료한 분할 기준으로 다음 순서가 정해진다.
- 루틴 밖 자유 운동은 기록만 남고 다음 운동 계산에는 반영되지 않는다.
- 유산소, 기타도 루틴 안의 분할에 포함되어 있으면 동일하게 루틴 진행에 반영한다.
- 취소한 운동은 기록에는 남지만 다음 운동 계산에는 반영되지 않는다.
- 운동 시간과 관계없이 종료된 세션은 완료 기록으로 저장한다.
- 하루에 여러 개의 루틴 운동을 완료하면 완료 횟수만큼 루틴이 진행된다.
- 루틴의 마지막 분할을 완료하면 다시 첫 번째 분할로 순환한다.
- 루틴의 구성과 순서는 사용자가 직접 바꾸기 전까지 자동으로 바뀌지 않는다.
- 루틴 수정 후 다음 운동 시작점은 사용자가 직접 선택한다.
- 운동 기록을 나중에 수정하거나 삭제해도 다음 운동은 자동으로 재계산하지 않는다.
- 다음 운동이 어긋났다고 느끼면 사용자가 루틴 설정에서 직접 시작점을 바꾼다.

## 8. 핵심 기능

### 8.1 운동 시작과 종료

사용자는 홈 화면 또는 위젯에서 다음 운동을 바로 시작할 수 있다.

주요 액션:

- 다음 운동 시작
- 루틴 안의 다른 분할 선택 후 시작
- 루틴 밖 자유 운동 시작
- 운동 종료
- 운동 취소
- 운동 중 운동 대상 변경

운동 종료 시 저장되는 정보:

- 시작 시간
- 종료 시간
- 총 운동 시간
- 운동 부위 스냅샷
- 연결된 루틴
- 상태: 완료 또는 취소
- 메모, 선택 사항

운동 취소도 기록으로 남긴다. 취소된 기록은 루틴 진행에는 반영하지 않으며, 사용자가 기록 상세에서 수정하거나 삭제할 수 있다.

과거 기록은 스냅샷으로 저장한다. 루틴이나 운동 부위 이름을 나중에 수정하더라도 과거 기록의 표시 내용은 당시 기준으로 유지한다.

### 8.2 홈 화면

홈 화면은 핏로그의 중심 화면이다.

운동 중이 아닐 때 홈 화면은 다음 운동을 시작하기 위한 화면이다. 사용자는 홈 화면에서 다음 운동을 확인하고, 바로 운동을 시작할 수 있다. 필요하다면 다음 운동이 아닌 루틴 안의 다른 분할을 선택하거나, 루틴 밖 자유 운동을 시작할 수도 있다.

운동 중일 때는 홈 화면 자체가 운동 중 화면 역할을 한다. 별도의 운동 중 화면으로 이동하지 않아도, 홈 화면에서 현재 운동 상태를 바로 볼 수 있다.

홈 화면은 세 가지 상태를 처리한다.

운동 전 상태:

- 다음 운동
- 해당 루틴에 포함된 운동 부위
- 운동 시작 액션
- 루틴 안의 다른 분할 선택
- 루틴 밖 자유 운동 선택
- 최근 히트맵
- 이번 주 운동 횟수
- 총 운동 시간
- 최근 기록

운동 중 상태:

- 운동 중 상태
- 현재 운동 부위
- 시작 시간
- 경과 시간
- 운동 종료 액션
- 운동 취소 액션
- 운동 변경 액션
- 필요하다면 최근 기록 또는 히트맵은 낮은 우선순위로 배치

운동 후 상태:

- 오늘 완료한 운동
- 운동 시간
- 다음 운동
- 최근 히트맵
- 이번 주 운동 횟수
- 총 운동 시간
- 최근 기록

### 8.3 루틴 설정

사용자는 자신의 운동 루틴을 설정한다.

루틴 설정에서 다루는 개념:

- 운동 부위
- 루틴
- 분할
- 각 분할에 포함된 운동 부위
- 다음 운동 시작점

루틴 설정 화면에서 가능한 일:

- 기본 템플릿으로 루틴 만들기
- 운동 부위 추가
- 운동 부위 보관 또는 삭제
- 루틴 안에 분할 추가
- 분할 이름 수정
- 분할에 포함된 운동 부위 수정
- 분할 순서 변경
- 분할 삭제
- 다음 운동 시작점 선택

### 8.4 기록 목록과 기록 상세

기록 목록에서는 완료, 취소, 진행 중 세션을 모두 확인할 수 있다.

기록 목록에서 보여줄 정보:

- 운동 날짜
- 운동 부위
- 상태
- 운동 시간
- 루틴 운동인지 자유 운동인지 구분

기록 상세에서 가능한 일:

- 운동 상태 수정
  - 완료
  - 취소
  - 진행 중
- 시작 시간 수정
- 종료 시간 수정
- 운동 대상 수정
  - 루틴 운동
  - 자유 운동
- 메모 수정
- 기록 삭제

기록을 수정하거나 삭제해도 다음 운동은 자동으로 재계산되지 않는다. 다음 운동이 어긋났다면 루틴 설정에서 다음 운동 시작점을 직접 조정한다.

### 8.5 위젯

MVP 위젯은 두 가지 타입으로 제공한다.

#### 위젯 1: 운동 시작/종료

운동 실행을 빠르게 하기 위한 위젯이다.

상태별 동작:

- 운동 전: 다음 운동 표시, 운동 시작
- 운동 중: 현재 운동 부위 표시, 경과 시간 표시, 운동 종료
- 운동 후: 완료 상태 표시, 완료한 운동과 운동 시간 표시

운동 종료 후 위젯 1은 당일 자정까지 완료 상태를 표시한다. 다음 날이 되면 다시 다음 운동 시작 상태로 돌아간다.

위젯 1에서는 루틴 안의 다른 분할 선택, 자유 운동 선택, 루틴 수정, 기록 수정은 제공하지 않는다. 세밀한 조작은 앱 안에서만 수행한다.

#### 위젯 2: 히트맵 캘린더

운동 기록을 빠르게 확인하기 위한 위젯이다.

표시 타입:

- 7일 히트맵
- 30일 히트맵

작은 위젯은 7일 히트맵을 우선하고, 중간 또는 큰 위젯은 30일 히트맵을 우선한다.

iOS에서는 홈 화면 위젯과 Live Activity 경험을 우선 검증한다. Android 위젯과 고정 알림은 iOS MVP 반응 확인 후 확장한다.

### 8.6 운동 히트맵

운동 기록을 7일, 30일 단위로 보여준다.

색상 기준은 운동 시간으로 단순화한다.

- 운동 안 함: 빈 칸
- 30분 미만: 약한 색
- 30분 이상 60분 미만: 중간 색
- 60분 이상 90분 미만: 진한 색
- 90분 이상: 가장 진한 색

하루에 여러 번 운동한 경우에는 해당 날짜의 총 운동 시간을 합산한다. 취소한 운동은 히트맵과 운동 시간 통계에는 포함하지 않는다.

### 8.7 운동 기록 대시보드

앱에서는 위젯보다 더 자세한 운동 기록 대시보드를 제공한다.

구성:

- 7일 히트맵
- 30일 히트맵
- 이번 주 운동 횟수
- 총 운동 시간
- 부위별 운동 시간
- 최근 운동 기록 요약

1. 홈 화면
   - 운동 전 상태
   - 운동 중 상태
   - 운동 후 상태
2. 루틴 설정 화면
3. 기록 목록 화면
4. 기록 상세 화면
5. 운동 기록 대시보드
6. 설정 화면

기존처럼 “운동 중 화면”을 별도 주요 화면으로 두기보다는, 홈 화면 안에서 운동 중 상태를 직접 처리하는 것이 MVP의 핵심 흐름에 더 적합하다. 운동 중 화면은 필요하다면 보조 상세 화면이나 모달로 둘 수 있지만, 사용자의 기본 흐름은 홈 화면에서 끝나는 방향으로 정리한다.

## 10. MVP 제외 범위

MVP에서는 기능을 늘리지 않고 운동 시작, 종료와 루틴 기반 기록에 집중한다.

제외 기능:

- 세트 기록
- 중량 기록
- 반복 횟수 기록
- 운동 종목 DB
- AI 코칭
- 식단 기록
- 체중 기록
- 커뮤니티
- 친구 공유
- 클라우드 동기화
- 구독 결제
- 1년 히트맵
- 운동 일시정지
- 운동 중 여러 구간 분리 기록
- 위젯에서 루틴 안의 다른 분할 선택
- 위젯에서 자유 운동 선택
- 위젯에서 루틴 설정
- 위젯에서 기록 수정

## 11. 최종 MVP 정의

사용자가 자신의 루틴을 설정하면 앱이 다음 운동을 안내하고, 사용자는 앱 또는 위젯에서 운동을 시작/종료하며, 앱에서는 자유 운동과 기록 관리를 수행하고, 기록은 7일/30일 히트맵과 대시보드로 쌓이는 앱.

## 12. 기술 스택

### App

- React Native + Expo
- TypeScript
- Expo Router

빠른 MVP 개발과 iOS/Android 확장을 고려해 React Native 기반으로 개발한다.

Expo Go만으로는 위젯, Live Activity, 커스텀 네이티브 기능 테스트가 어렵기 때문에 실제 네이티브 기능 검증은 Expo Development Build를 사용한다.

### State / Storage

- Zustand
- expo-sqlite

운동 세션, 루틴, 운동 부위, 히트맵 데이터는 로컬 DB에 저장한다.

권장 역할 분리:

- SQLite: 영속 데이터의 원천

MVP에서는 로그인과 서버 동기화 없이 Local-first 구조로 시작한다.

- iOS Widget

- Android App Widget

Android 운동 중 상태는 iOS MVP 반응 확인 후 앱 위젯과 고정 알림 형태로 확장한다. 실제 구현 전 Foreground Service 요건을 별도로 검증한다.

MVP에서는 백엔드를 사용하지 않는다.

초기 버전은 서버 없이 로컬 기록만 제공한다. 추후 백업, 기기 간 동기화, 계정 기능이 필요해지면 Supabase 또는 Firebase를 검토한다.

## 16. 기술 리스크

### iOS Live Activity와 Widget

Expo의 iOS 위젯/Live Activity 기능은 Development Build가 필요하다. Expo Go에서는 사용할 수 없다.

초기 개발 단계에서 iPhone 실제 기기로 기술 스파이크를 진행해야 한다.

구현 참고:

- 히트맵 iOS 위젯은 Expo JS 위젯 뷰가 아니라 SwiftUI `GeometryReader` 기반 네이티브 렌더러로 표시한다.
- 앱 미리보기와 실제 위젯은 공통 스펙 값을 공유하되, renderer는 RN과 SwiftUI로 분리한다.
- `/ios`는 생성 산출물이므로 히트맵 위젯 SwiftUI 패치는 `plugins/with-loofit-heatmap-widgets.js`에서 재생성한다.
- 히트맵 셀 크기는 컨테이너 너비, padding, gap, column 수로 동적 계산한다.

참고:

- https://docs.expo.dev/versions/latest/sdk/widgets/
- https://docs.expo.dev/develop/development-builds/introduction/

### Android Foreground Notification

운동 중 고정 알림은 일반 알림보다 Foreground Service에 가깝다.

Android 14 이상에서는 foreground service type 선언과 Play Console 제출 요건이 필요할 수 있다. Android는 iOS MVP 반응 확인 후 확장한다.

참고:

- https://developer.android.com/develop/background-work/services/fgs
- https://support.google.com/googleplay/android-developer/answer/13392821

### 로컬 데이터 정합성

루틴, 운동 부위, 과거 기록이 서로 영향을 주지 않도록 기록 저장 시 운동 부위 스냅샷을 남긴다.

### 위젯과 앱 데이터 정합성

앱을 열지 않고 위젯에서 운동을 시작하거나 종료할 수 있어야 한다. 이를 위해 iOS에서는 App Group 공유 저장소와 AppIntent 기반 동작을 검증한다.

위젯에서 DB를 직접 변경하는 구조는 앱 내부 도메인 로직과 중복될 수 있으므로, 정책 변경 시 앱 로직과 위젯 로직이 어긋나지 않도록 관리해야 한다.

### 다음 운동 예외 정책

다음 운동 계산은 단순하게 시작하되, 아래 정책을 명시적으로 처리해야 한다.

- 다음 운동과 다른 분할을 선택해 완료하면 실제 완료한 분할 기준으로 다음 운동이 정해진다.
- 루틴 밖 자유 운동은 기록만 남기고 다음 운동 계산에는 반영하지 않는다.
- 유산소, 기타도 루틴 안의 분할에 포함되어 있으면 루틴 운동으로 처리한다.
- 하루에 여러 개의 루틴 운동을 완료하면 완료 횟수만큼 루틴이 진행된다.
- 운동 취소 세션도 기록으로 남기되, 다음 운동 계산에는 반영하지 않는다.
- 운동 시간과 관계없이 종료된 세션은 기록으로 저장한다.
- 루틴 구성과 순서는 사용자가 직접 루틴 설정을 변경하기 전까지 자동으로 바뀌지 않는다.
- 루틴 수정 후 다음 운동 시작점은 사용자가 직접 선택한다.
- 운동 기록 수정/삭제는 다음 운동을 자동 재계산하지 않는다.
- 운동 중 변경은 같은 세션의 최종 운동 대상을 바꾸며, 경과 시간은 유지한다.
- 앱을 다시 열었을 때 active 세션이 있으면 홈 화면에서 운동 중 상태를 복구한다.
- 장시간 방치된 active 세션도 자동 종료하거나 자동 삭제하지 않고 그대로 유지한다.
- 과거 기록은 저장 시점의 운동 부위 스냅샷으로 표시한다.

## 18. 첫 번째 마일스톤

목표: 앱 내부에서 루틴을 만들고, 다음 운동을 시작/종료하고, 기록이 히트맵에 반영되는 흐름을 완성한다.

완료 조건:

- 기본 운동 부위가 생성된다.
- 사용자가 루틴을 생성한다.
- 홈 화면에서 다음 운동이 표시된다.
- 다음 운동, 루틴 안의 다른 분할, 자유 운동을 시작할 수 있다.
- 운동 시작 후 홈 화면이 운동 중 상태로 전환된다.
- 앱을 다시 열어도 active 세션이 홈 화면에서 복구된다.
- 운동 종료 시 기록이 저장된다.
- 운동 취소 시 취소 기록이 저장된다.
- 7일/30일 히트맵에 기록이 반영된다.
- 운동 기록 대시보드에 기록이 반영된다.
- 최근 운동 기록에서 상세 내용을 확인할 수 있다.
